# Template contract

Every mode ships one template here: a complete HyperFrames project with the copy, data and palette pulled out into files the agent fills. `scripts/new-film.mjs` copies a template into a new film folder, adds the shared runtime as `lib/` (stamped with `lib/VERSION`), writes the `PLAN.md` skeleton, and downloads the fonts; it exits non-zero when a font cannot be downloaded. Nothing in a template is generated by a video model; every picture is drawn in code, and the sound is synthesised in code.

## Files

```
<mode>/
├── TEMPLATE.md     slots, scene registry with parameters and character limits, a worked example — the agent reads this before editing content.js
├── content.js      the film: palette id, scenes and copy (optional bpm, target). The only file edited for an ordinary film.
├── timing.rules.js how long each scene type needs: beats of choreography, text to read by tier, steps, ceiling, turns, key events, tempo range
├── palettes.js     the mode's palette presets. Choose one by id; never invent hex values.
├── index.html      the composition. Reads content.js and palettes.js; draws every frame from render(t).
├── score.mjs       sound: builds the music bed and effects from content.js on the same beat grid, writes assets/audio/mix.wav
├── fonts.json      font files with their download and licence URLs and @font-face descriptors (see Fonts)
├── package.json    scripts: setup, fit, audio, check, snapshot, render, film
└── hyperframes.json
```

Optional per mode: `data/` (computed numbers for data films), `run.js` (the algorithm run for explainers), `scenes/` (one module per registered scene when index.html would pass ~800 lines).

After `new-film.mjs`, the film folder also has:

- `PLAN.md` (required): concept sentence, through-line, banned defaults (copied as candidates from the mode card's "Factory defaults"), nearest reference, the motif table against it, and the beat table that `npm run fit` writes between its `<!-- fit:begin -->` / `<!-- fit:end -->` markers. Filled before `content.js`. **No `PLAN.md`, no render:** `lib/fit.mjs` exits 1 without it, and `audio`, `snapshot` and `film` all run `fit` first. Unfilled `<!-- fill -->` sections are a warning. `node lib/fit.mjs . --no-plan` skips the check, for tests of the runtime only.
- `lib/` (copy of `assets/runtime/`) with `lib/VERSION`: the timing API, a hash of the runtime at copy time and the date, so a film whose `lib/` has drifted from the Skill's runtime can be spotted.
- `assets/fonts/` (downloaded from one pinned google/fonts commit, `GOOGLE_FONTS_COMMIT` in `setup-fonts.mjs`; a failed download writes no `fonts.css` and exits 1) and `assets/audio/` (written by `npm run audio`).
- `renders/timing.json`, written by every `npm run fit` (see "Key events and timing.json").

## Length follows content

No film has a fixed length, and no scene has hand-typed bars. `timing.rules.js` states, per scene type, the beats its choreography takes, the text the viewer reads while it holds, its steps and its ceiling; `lib/timing.js` `fit(content, rules)` turns that into bars per scene and returns the duration. `index.html`, `score.mjs` and `lib/fit.mjs` all call `fit()`; `npm run fit` prints the timing table, stamps the duration onto `index.html`'s `data-duration` attributes (HyperFrames reads them statically) and writes `renders/timing.json`. The full rules format is the header of `lib/timing.js` (`TIMING_API = 3`). The `api` a rules file declares decides which limits are errors:

| `api` | Limits that are errors | Status |
|---|---|---|
| 3 | the four tiers of change (principles 4 and 5, owner-approved 2026-10-19): text per state, holds, compositions ≤ 6 s, T0 gaps, T1 lengths, T2 count, spacing and repeats, T3 count and climax position | the target for every template |
| 2 | the page ceilings of 2026-10-18: ≤ 12 primary words a page (`pageWords`); a step's still ≤ 1 bar and the last ≤ 1½ (`maxStillBars`, `lastStillBars`); a page ≤ 2 bars (`max`), ≤ 4 with `steps` (`pageMaxBars`), past that only a rest or a climax with a `reason`. The tiers are measured and reported as one INFO note | supported unchanged until each template migrates |
| 1 (none) | the api 2 ceilings as warnings | legacy |

Rules common to every api:

- **Reading, three tiers.** `read(s, ctx)` returns strings (primary) and `{ text, tier, at, claim }` items. *Primary* (titles, claims, numbers, commands, questions): 0.3 s a word, and a scene's primary text adds up in order, each item starting at its `at` or when the previous one has been read. *Glance* (labels, corner notes, stage names, title-block fields): ≤ 6 words and repeated elsewhere or safe to delete (say which in a comment); fully still ≥ 1 s, in parallel, never added up; a glance item over 6 words is counted as primary and reported. *Word* (slammed one word at a time): once the line is complete it holds 0.3 s × its words. Counting is `units(text)`: Latin by word, CJK by character (`cjkCharSec` 1/9 s). A type that needs its own `need(s, g, ctx)` still reads through `ctx.reading(items)`; no template keeps a reader of its own.
- **Grid and turns.** Scene lengths are whole `unit`s, default one beat (`1 / beatsPerBar` bar); a mode may coarsen it when its music needs it (see its card). A type with `turn: true` (chapter change, claim) starts on a bar line; the part bar before it lengthens the previous scene and is reported as the turn's `pad`.
- **Phrase.** The total is rounded up to `phrase` bars. The extra is shared out first: one beat at most per scene (`phraseShareBeats`), from the back, over scenes that are not rests or turns and are below their ceiling. After the last turn any number of grid steps may go; a segment before a turn (between two turns, or before the first) takes only whole bars, spread over its scenes, so every turn stays on its bar line. Only what is left goes to the closing scene (`absorb`), last. Shares come in whole grid units, so a mode whose `unit` is longer than one beat shares nothing unless it raises `phraseShareBeats` to its unit. The table and `timing.json` show each scene's `phraseShare`. The closing scene carries a second move that lands on the downbeat of the last bar, so the extra is never a dead hold.
- More copy or more scenes make a longer film; the tempo does not change to hide it.
- `content.target` (seconds, optional) asks for a length: the tempo moves inside the mode's range to meet it; what the range cannot absorb is reported as bars to cut or add, never padded with holds or squeezed below reading time.
- A scene may set `bars` by hand to lengthen it for rhythm (a rest, a drop); a hand value below the reading need or above the ceiling is reported and overridden.
- Inside a scene, entrances are timed in beats from the scene start and exits in beats before its end, so a longer scene lands at the same moment and holds longer; nothing is scaled to the scene's length.
- Templates hand over briskly: a type's `in` is at most 2 beats (`entryBeats`) unless it is a turn, a rest or a climax (a warning); the next scene enters while the previous one leaves, and exits take at most two thirds of the entrance's time. `rest` counts only as boolean `true`, on the type or the scene; any other scene field called `rest` is reported, so content can never switch a ceiling off.

### api 3: the four tiers

At 120 BPM one beat is 0.5 s; every limit in beats follows the tempo. Every value is in `DEFAULTS` and can be overridden by the rules file under the same name (a mode that departs says why on its card).

| Tier | Declared as | Limit (`DEFAULTS` key) | Checked by |
|---|---|---|---|
| Text per state | `read()` items; items sharing an `at` (to the frame) enter together; `claim: true` on a claim | primary words entering together ≤ 5 (`stateWords`), ≤ 8 with a claim (`claimWords`); glance and word-at-a-time items are not counted | `fit()`: error |
| Step holds | `steps()` returns seconds, or `{ still, pause: true }` for a step where a claim is read | each ≤ 2 beats (`holdMaxBeats`), a pause ≤ 2 bars (`pauseMaxBars`) | `fit()`: error at the need; after the grid, a turn's pad and the phrase share: warning (see below) |
| Scene ceiling | `max` (bars) | default `sceneMaxSec` (6 s) in whole units at the fitted tempo; no 2- or 4-bar page ceilings, no 12-word page cap | `fit()`: error when the reading need exceeds it |
| Holds | `holds: [{ from, to, scene, pause }]` | ≥ 0.2 s (`holdMinSec`), ≤ 2 beats; `pause: true` ≤ 2 bars; more than 2 pauses a film warns (`claimsMax`); rest scenes excepted | `events()`: error; check-film FAIL on the pixels (longest still per scene, pauses excepted) |
| T0 micro | `micro: [{ t, scene, what }]`; keys, scene starts, shots, expressive starts and peaks count as onsets too | median gap ≤ 2 beats (`microMedianBeats`), every gap ≤ 4 beats (`microMaxGapBeats`) outside rest scenes and pause holds; no `micro` at all warns | `events()`: error; check-film FAIL on the declared events, picture onsets INFO |
| T1 scene | scene starts plus `shots: [{ t, scene, what }]` (a new composition inside a scene) | median 2–3 s (`sceneMedianSec`; over the top error, under the bottom warning); each ≤ 6 s (`sceneMaxSec`) unless its scene is a rest, or a climax with a `reason`; ≥ 2 in the first 5 s (`firstScenes`, `firstSec`); CV ≥ 0.3 (`sceneCV`); no run of 3 that speeds up or slows down warns | `events()`: error; check-film FAIL |
| T2 expressive | `expressive: [{ t, dur, device, variant, scene }]` (`beats` instead of `dur` is converted) | count in [floor(D / 12), ceil(D / 8)] (`expressiveEverySec` [8, 12]); one `device` ≤ 3 times (`expressiveSameMax`); the same device with the same `variant` twice in a row is an error; `dur` ≤ 2 beats (`expressiveMaxBeats`), a missing `dur` warns; two neighbours (or the film's start and the first, the last and the film's end) more than 12 s apart warn; a `device` that is not an id of `runtime/transitions` or `runtime/handoffs`, nor listed in the rules' `devices`, warns | `events()` and `lib/fit.mjs`: error; check-film FAIL, large-area changes INFO |
| T3 peaks | `peaks: [{ t, kind, climax, scene }]`, kind `hook` \| `claim` \| `reveal` \| `lockup` | 2–3 a film (`peakCount`); at most one `climax: true`, at 60–85 % of the length (`climaxAt`); no climax marked, a run into it that is not the shortest, or no release after it warn | `events()`: error; check-film FAIL, the loudest moment INFO |

**Steps at the fitted length.** The grid, a turn's pad and the phrase share make a scene longer than its need. `fit()` then calls `steps()` again with `ctx.dur`, the scene's fitted seconds (`ctx.dur` is undefined in the first call, at the need). A type that reads `ctx.dur` returns its holds at that length, so slack it fills with moves (tail moves, a second highlight) is not counted, and each hold is checked as returned; a type that does not read it gets the slack added to its last step's hold. A type that always fills the slack with moves of its own may declare `fillsSlack: true` instead: it is not checked after the grid, and its `events()` holds and the T0 gaps measure it. These are warnings; the holds at the need stay errors (2026-10-19).

**Template devices.** A template that owns a T2 device the libraries do not have (plakat's full accent wipe, phosphor's fibre burst) lists its ids in the rules: `devices: ['plakat-accent-wipe']`. `lib/fit.mjs` then knows them; any other unknown id warns.

What the tiers cannot see stays on the checklist: each T0 brings one new piece of information; a new topic enters only at a scene change; a related transformation is the default change; reading time counts while the text is readable and still, so other things may change during it only if they are not new text and do not cross it. A turn's `pad` and the phrase share can lengthen a scene past 6 s; the T1 check catches it.

`npm run fit` prints, under the table, one line of tier measures (`tiers: T0 … · T1 … · T2 … · T3 …`) and each failure as an error with its time. Below api 3 the same line arrives as one INFO note listing what would fail, which is the migration's to-do list.

### Migrating a template from api 2 to api 3

1. Run `npm run fit` on the shipped `content.js` and keep the INFO note: it names every tier that would fail and the reading states over five words.
2. **Text per state.** Split every primary line over five words into phrases that enter one after another: give each phrase its own `at` in `read()` (or `ctx.reading()`) and its own entrance in the choreography. Mark the one or two claims with `claim: true` (≤ 8 words). Make word-by-word or phrase-by-phrase entry the type's default.
3. **Holds and steps.** Rewrite `steps()` so no hold after a landing exceeds 2 beats: put a T0 change that is not new text (a highlight moving, a count ticking, the line growing, the container reshaping) inside long reading windows. Return `{ still, pause: true }` for the step where a claim is read, and give its hold `pause: true` in `events()`. Every declared hold is ≥ 0.2 s.
4. **Compositions.** Lower `max` on types that ran to 4 bars; split a page that needs more than 6 s, or declare `shots` where the camera or layout moves to a new composition inside it (and raise `max` to fit). Vary the lengths: a CV under 0.3 is an error, so give the scene types different beat counts and build runs that speed up into the climax and slow after it. Two compositions in the first 5 s.
5. **T0.** Return `micro` events from the same choreography tables the picture draws from (every word or phrase entering, every highlight jump, count tick or morph step), so they cannot drift. Fill any gap over 4 beats outside rests.
6. **T2.** Choose the mode's devices from `runtime/transitions` and `runtime/handoffs` (the mode card lists them), place one about every 8–12 s, at most 2 beats each, vary direction, origin or colour role between two uses of one device and record it in `variant`, and return them as `expressive`. Each lands with a sound in `score.mjs`.
7. **T3.** Mark 2–3 `peaks` (hook, claim or reveal, lock-up) and `climax: true` on the one at 60–85 % of the length; shorten the compositions before it and leave a release after it. The music may drop out before the lock-up.
8. Set `api: 3`, run `npm run fit` until it reports no errors, render, and run `check-film`: the tier rows must PASS and `scene stills` must not FAIL. Update the TEMPLATE.md Length table and the mode card's timing values, citing principles 4 and 5.

## Key events and timing.json

`check-film` measures the film against what the template says happens, not against guesses from the pixels. A type may give `events(s, g, ctx)` (times in seconds from the scene start), and `timing.rules.js` may give `events(scenes, g, content)` at the top level (absolute times), returning:

```js
{
  keys: [{ t, kind, scene }],    // kind: turn | land | stamp | accent | claim | end; on a beat ±2 frames,
                                 // turn and claim on a bar line; drop: true marks the music's drop, where
                                 // check-film allows the loudness jump
  holds: [{ from, to, scene, pause }],  // the still windows after the protagonist lands: stillness and reading are
                                 // measured here; pause: true where a claim is read (api 3: ≤ 2 bars, else ≤ 2 beats)
  handoffs: [{ t, scene }],      // morph hand-off frames: the frame difference across them is measured
  mask: [x, y, w, h],            // the content area, without the persistent frame: motion is measured only here
  // api 3 tiers (see "api 3: the four tiers"); any api may give them, below 3 they are INFO
  micro: [{ t, scene, what }],   // T0 changes
  shots: [{ t, scene, what }],   // T1 compositions inside a scene
  expressive: [{ t, dur, device, variant, scene }],  // T2 transitions; device: an id of runtime/transitions, runtime/handoffs or rules.devices
  peaks: [{ t, kind, climax, scene }],               // T3: hook | claim | reveal | lockup
}
```

The same choreography tables that place the picture and the sound produce these events, so they cannot drift. For example, a type whose phrases enter on beats 0, 1 and 2, with a whip push into the next scene on its last beat:

```js
events: (s, g) => ({
  micro: s.phrases.map((p, k) => ({ t: k * g.beat, what: p })),       // T0: one phrase a beat
  holds: [{ from: (s.phrases.length - 1) * g.beat + 0.25, to: (s.phrases.length + 1) * g.beat }], // landed, ≤ 2 beats
  expressive: s.out === 'whip' ? [{ t: (s.end - s.start) - g.beat, beats: 1, device: 'whip-push', variant: 'left' }] : [],
  peaks: s.claim ? [{ t: 0, kind: 'claim', climax: true }] : [],
}),
```

`npm run fit` checks every key against the grid, runs the tier checks and writes `renders/timing.json`:

```js
{ api: 3, rulesApi,              // format version; the api the rules declare (≥ 3: check-film fails the tiers)
  duration, bpm, beatsPerBar, t0, unit, phrase,
  limits: { wordSec, cjkCharSec, glanceSec, glanceMaxWords, maxStillBars, lastStillBars, max, pageMaxBars, pageWords, entryBeats,
            phrase, phraseShareBeats, fps, keyFrames, holdMinSec, holdMaxBeats, pauseMaxBars, stateWords, claimWords, claimsMax,
            sceneMaxSec, sceneMedianSec, firstSec, firstScenes, sceneCV, microMedianBeats, microMaxGapBeats,
            expressiveEverySec, expressiveSameMax, expressiveMaxBeats, peakCount, climaxAt },
  accent,                        // #rrggbb, when known
  scenes: [{ i, type, start, end, beats, bars, need, max, pad, phraseShare, reading: { primary, glance, from },
             rest, turn, climax, still?, pause?, reason? }],
  keys, holds, handoffs, mask, micro, shots, expressive, peaks,
  tiers: { t0, t1, t2, t3, holds },  // the measures of lib/timing.js tiers()
  notes }
```

`limits` are the effective values (defaults with the rules' overrides), so check-film measures against the same numbers `fit()` used, and runs the same `tiers()` function on the arrays. `accent` comes from `rules.accent` (a hex, or `content => hex`), else `content.accent`, else `palettes.js[content.palette].accent`; it is omitted when none is a `#rrggbb` hex. A scene's `max` is `null` when it has no ceiling (a rest). `pad` and `phraseShare` are in beats, `reading` in seconds, `mask: null` means the whole frame. A template without `events()` still gets one `turn` key at the start of every turn scene, and no holds. An `events()` that throws is an error and `npm run fit` exits 1. check-film reads api 2 files too (no tier arrays: the declared tier rows report what the scene table and keys alone give, as INFO).

## content.js

An ES module, imported by the browser and by Node:

```js
export default {
  palette: 'cobalt',       // an id from palettes.js
  seed: 1,                 // all randomness derives from this
  // bpm: 120,             // optional; default and range come from timing.rules.js
  // target: 45,           // optional seconds; see "Length follows content"
  meta: { title: '...', url: '...' },
  scenes: [ { type: 'claim', /* type-specific slots; bars only to lengthen on purpose */ } ],
};
```

Scene `type` values come only from the mode's registry in TEMPLATE.md. Each slot has a character limit; copy that does not fit is rewritten shorter, never shrunk below the mode's minimum type size.

## Rules every template follows

- **Pure function of time.** `render(t)` paints the whole frame from `t` and content alone, wired through `lib/boot.js` (`hf-seek` per frame). Templates ported from GSAP timelines may instead build one paused GSAP timeline from content at init and register it as `window.__timelines.main`; either way no value depends on the previous frame.
- **Static timeline hook.** `hyperframes check` reads `index.html` statically, so a template that registers its timeline through `lib/boot.js` also carries an inline `<script>window.__timelines = window.__timelines || {};</script>` in the head; `boot.js` then registers `window.__timelines.main` once fonts are ready.
- **Copy is validated before render.** A template whose slots have limits beyond what `fit()` reads gives `validate(content)` on its rules (sync or async, returns error strings); `npm run fit` reports each as an error and exits 1. The page shows the same errors in a red banner on every frame (and as a page error) rather than rendering a blank film (ink, 2026-10-19).
- **Slow setup holds the renderer.** A `ready()` that takes more than a moment (a baked field to fetch and decode, a large data file) must hold the renderer from its first readiness check: pre-register the hold in the classic `<script>` in the head, next to the `__timelines` stub (`window.__hf.buildReady.main = new Promise((r) => (window.__hf.buildHold.main = r))`), and `lib/boot.js` settles it. Registered later, from the module, parallel render workers start capturing before the setup is done and render black frames (ink, 2026-10-19).
- **Transitions come from the libraries.** Hand-offs (`lib/handoffs/`) are created with `createHandoff(name, params)` in `ready()`, after the fonts, drawn with `h.draw(ctx, p, { dur })`, their rests with `h.still(ctx, 'from' | 'to')`, and with `ground: false` when layered over the template's own scene; frame-level transitions go through `lib/transitions/`; fast frames use `subframes(ctx, draw, t, { speed })` from `lib/canvas.js`. A template keeps a local extension only where a module cannot express its scene, and says why in TEMPLATE.md (morph, halftone and pulse do, 2026-10-19).
- **Deterministic.** No `Math.random()`, `Date.now()` or `performance.now()`; randomness from `lib/rng.js` seeded by `content.seed`.
- **Beat-locked.** Scene starts come from `lib/timing.js` `fit()`; every cut sits on a beat, key events (see above) on a beat ±2 frames and turns on a bar line, and `score.mjs` reads the same fitted scenes.
- **Fonts verified.** `lib/text.js` `fontsReady(families)` checks that every family, weight and style asked for resolves to a face from `fonts.css` that actually loaded; otherwise it paints a red banner over every frame and raises a page error, which `hyperframes check` reports, so a film never renders silently in a fallback font. Templates load their fonts through it rather than through `@font-face` rules of their own.
- **No network at render time.** GSAP loads from `lib/vendor/gsap.min.js` (pinned and hash-checked by `setup-vendor.mjs`), fonts from `assets/fonts/fonts.css` written by `setup-fonts.mjs`; data loads by `import`, never `fetch`.
- **No binary assets in the template.** No `.ttf`, `.woff`, `.wav`, `.mp3`, `.mp4`; no image over 200 KB. Fonts are downloaded by `fonts.json`, sound is synthesised by `score.mjs`, textures are generated from a seed.
- **Placeholders are real.** The shipped `content.js` is a complete, renderable example film (the subject of the mode's source film, with every number embedded), so `npm run film` works straight after `new-film.mjs`.
- **Measured layout.** Text positions come from measured widths (`lib/text.js`) or the mode's grid, never from offsets tuned to one string. Lines wrap through `lib/text.js` `wrap()`, whose break opportunities come from one function, `breaks()`, so line breaking for Chinese can replace it in one place.

## Fonts

`fonts.json` lists one entry per font file; `lib/setup-fonts.mjs` downloads each file and its licence and writes one `@font-face` per entry into `assets/fonts/fonts.css`:

```json
[{ "family": "Archivo", "file": "Archivo-VF.ttf", "url": "https://raw.githubusercontent.com/google/fonts/main/ofl/archivo/Archivo%5Bwdth,wght%5D.ttf",
   "weight": "100 900", "stretch": "62% 125%", "style": "normal",
   "license": "OFL-Archivo.txt", "licenseUrl": "https://raw.githubusercontent.com/google/fonts/main/ofl/archivo/OFL.txt" }]
```

- `weight`: a number, `normal` / `bold`, or a range (`"100 900"`, a variable font's `wght` axis). Default 400.
- `stretch` (optional): a percentage, a range (`"62% 125%"`, a variable font's `wdth` axis) or a keyword (`condensed`). Written as `font-stretch`, so canvas and CSS can ask for any width inside the range.
- `style`: `normal`, `italic` or `oblique` with an optional angle range. Default `normal`.
- google/fonts URLs may name `main`; they are fetched from the pinned commit. A descriptor the browser could not parse would drop the face silently, so `setup-fonts.mjs` rejects it, and any failure exits 1 without writing `fonts.css`.

Templates load fonts only through `fonts.css`, never through `@font-face` rules of their own in `index.html`; whatever a template needs (a width axis, an italic) goes into `fonts.json`.

The default value renders exactly as the template did before the field existed (stills compared pixel for pixel when it was added). ## Cut-downs for a reel

A film that is cut into a longer one (a showcase, a launch film's sting, a demo inside a reel) needs a first frame that is already the mode's world, a settled last half second, and a short chain. Each template's shortest cut (2026-10-19):

| Template | How | Shortest |
|---|---|---|
| thread | leave out `open`/`word` and `tracks`/`review` as whole parts (TEMPLATE.md, "Short chain") | storyboard → merge → close, 11.25 s at 128 bpm |
| ink | open on `bloom` | bloom → name → cta, 10.6 s at 136 bpm |
| plakat | `opening: 'set'`; the last scene does not exit | problem → claim, 11.25 s at 128 bpm |
| blueprint | `excerpt: true`: 2–9 sheets, no release card | 2 sheets, 9.6 s at 100 bpm |
| phosphor | `boot` → `end`; `end.dim: false` | 10.6 s at 136 bpm |
| tally | `edges: 'cut'` | count → columns, 12 s at 120 bpm |
| trace | `edges: 'cut'` | hook and two merges, 10 s at 96 bpm |
| morph | open on `solid`; keep the closing `cmd` | solid → unfold → mark, 12 s at 120 bpm |
| halftone | `edges: 'cut'` | card → lockup, 12 s at 120 bpm (8 s with the name alone) |
| pulse | ask → ask → search → reveal (`rest: true`) | 12 s at 120 bpm |

The switches differ because the templates do; a later version may unify them under `edges`.

## package.json scripts

```jsonc
{
  "type": "module",
  "scripts": {
    "setup": "node lib/setup-fonts.mjs .",
    "fit": "node lib/fit.mjs .",           // also writes renders/timing.json; exit 1 without PLAN.md
    "audio": "node lib/fit.mjs . && node score.mjs",
    "check": "npx --yes hyperframes@0.8.163 check",
    "snapshot": "node lib/fit.mjs . && npx --yes hyperframes@0.8.163 snapshot",
    "render": "npx --yes hyperframes@0.8.163 render --fps 30 --workers ${HF_WORKERS:-auto} --output renders/film.mp4",
    "film": "npm run audio && npm run check && npm run render"
  }
}
```

`check` needs `assets/audio/mix.wav`, so run `npm run audio` (or `npm run film`) once before a bare `npm run check`.

`HF_WORKERS` caps the render's parallel workers (each a Chrome process of about 256 MB): `HF_WORKERS=2 npm run film` on a machine others render on too. Unset, HyperFrames picks (`auto`). The `${HF_WORKERS:-auto}` form needs a POSIX shell, which npm uses for scripts on macOS and Linux (ink adds its `bloom-bake.mjs` step before the render).

## Sound

`score.mjs` imports `./lib/audio/index.mjs` (see `assets/runtime/audio/README.md`): a beat-grid sequencer, synthesised voices, a bed preset per mode, and a master that normalises to −14 LUFS, true peak ≤ −1.5 dBTP. The master then encodes the mix to AAC 192k as the renderer does and keeps that encode's true peak ≤ −1.2 dBTP (re-mastering with a lower true-peak target if needed); otherwise HyperFrames lowers the whole mix to stay under −1 dBTP ("Audio lowered by X dB" in the render log) and the film misses −14 LUFS. Every score fades in over 60 ms by default, so a film that opens on a hit does not hand the encoder a full-scale first transient (2026-10-19). Every picture event that deserves a sound (a landing, a stamp, a cut) gets one at the same beat. An optional generated music file can replace the bed: put it at `assets/audio/bed.wav`, set `bed: { file: 'assets/audio/bed.wav', offset: <s> }` in content.js, and keep the bpm equal to the measured tempo.
