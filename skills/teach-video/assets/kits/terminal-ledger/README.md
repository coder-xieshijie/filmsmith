# terminal-ledger · light terminal × dot ledger

A style kit for explainers about software work: light terminal windows on paper, things that happen become marks that flow into a ruled ledger, counts pile up as hand-drawn dots and sort into coloured heaps. Extracted on 2026-10-28 from a three-minute explainer the owner approved; the director-and-segments workflow it serves was accepted as the default on 2026-10-29.

- Segment agents read only [CARD.md](CARD.md) (one page) and look at [ref/look.jpg](ref/look.jpg) (8 demo moments, then 8 component families shot from a temporary gallery project with `npm run shots -- --at …`).
- [starter/](starter/) is the project every film starts from (`scripts/new-film.mjs` copies it). Its two demo segments (`demo-a1`, `demo-a2`, illustrative data about sorting a week of email) run on [demo-shared/](demo-shared/) and pass `npm run check`; `npm run init` deletes them. To run the demo in a fresh copy: copy `demo-shared/` out of the skill, make its voice, track, music and fonts with `uv run <skill>/scripts/voice/voice.py tts track audio fonts --dir <copy>` (the committed timeline and word timestamps stay as they are), and point `film.json` `shared` at the copy.
- What every kit must contain and how to extract a new one: [../README.md](../README.md).

## Project layout

```
film.json      title, duration, shared (shared-assets dir), skill (where teach-video is), kit, avatar windows, hands, poster
handoff.json   segments and handoffs (init writes the skeleton, the director fills it)
anchors.txt    the director's anchor list → cues.js (generated)
segments/      one file per segment, <id>.js
tokens.js      colours, fonts, sizes, spacing, no-go zones — set only here
lib.js         one paused main timeline, stateful tweens (any seek gives the same frame), deterministic randomness
components/    one file per component, usage at the top
main.js        mounts the segments from handoff.json and gives each a ctx (take / give / hit)
build/         init, anchors, check, shots, render, finish, kit-sync, vendor (GSAP), browser (the engine's Chrome); hf.cjs is the only place the engine version is written
index.html     generated by build/assemble.cjs on every command
```

Media, fonts and GSAP are never committed: `assemble` copies sound and fonts from the shared assets into `assets/` and fetches GSAP into `vendor/`.

## Commands

The engine does whatever it can; the scripts only fill its gaps.

- `npm run init -- --shared <dir> --segments "abc:a1-c3,de:d1-e3,ez:e4-z1" [--title t] [--poster s] [--hands 4]`: turns a fresh copy into a film's skeleton. `film.json` gets the length from the timeline, presenter windows from `contract.json` `avatar_zone.windows_s`, a poster at the first segment's middle; `handoff.json` gets one segment per entry, cut by line IDs (`start`, `end`, `lines` from the timeline; a boundary at a scene change takes the scene's start, otherwise the midpoint of the silence between the two lines), with `goal`, `first` / `last` empty and `chapter` / `counter` null; each segment gets an `F.shell(ctx)` stand-in; the demo segments go; `anchors.txt` gets one anchor per line and `cues.js` is generated. `npm run check -- --no-hf` then passes as it is. It refuses to overwrite a director's segment files or anchors (`--force` starts over).
- `npm run anchors`: looks up `anchors.txt` in the shared `words.json` and rewrites `cues.js`. One anchor per line: `name lineID [word][#n][$] [±s] [!]` (no word = the line's start, `word$` = when the word ends, `#2` its second occurrence, `±s` a shift; `name 33.0` is a plain time, `name end` the film's end). A trailing `!` (or `!2.5`, the change's length in seconds, default 1.5) marks the start of a state change the narration names; the review packet shows each marked one as before / during / after. Write words as in the narration text; where the transcript misheard (digits, homophones) the text is aligned by edit distance and the anchor prints a note. A missing word, an ambiguous word without `#n`, an unknown line or a duplicate name is an error and leaves `cues.js` untouched. `npm run anchors -- <lineID> [word]` only prints times.
- `npm run check [-- --seg <id> | --from a --to b] [--no-hf]`: the skill's `scripts/geo-check.cjs`, the presenter reserve frame by frame, handoffs (given, in place, visible and not covered) and leftovers (`build/page-checks.cjs`), and the engine's `check --at-transitions` per 30 s; the last line is pass / FAIL with the report path. Reports are per range in `build/reports/`, so segments can be checked at the same time.
- `npm run shots -- --from a --to b` (or `--seg`, `--at`): the engine's `snapshot --at` takes the frames; the script tiles them into one sheet (long side ≤ 2000, each cell captioned with time and segment) and prints its path.
- `npm run hf -- <command>`: the pinned `npx hyperframes <command>`. Detail `snapshot --zoom`, side by side `compare`, against a reference video `snapshot --against <mp4>`, review frames `snapshot --review`.
- `npm run render`: collects the sound cues the segments registered, then the engine renders `renders/raw.mp4`; the engine's full output is in `build/reports/render.log`.
- `npm run finish`: checks every registered cue was mixed in (stops if not), sets −14 LUFS, bt709 tags, writes `renders/film.mp4`, `poster.jpg`, `contact-sheet.jpg`, asserts true peak ≤ −1.5 dBTP, runs the skill's `scripts/unit-check.sh` and deletes `raw.mp4`. Loudness of the mixed film, true peak, poster and contact sheet stay on ffmpeg: the engine's `normalize-audio` only sets one track's volume, and its snapshots render the source, not the delivered file.
- `npm run kit-sync [-- --check]`: copies the kit's film-independent parts (`build/`, `lib.js`, `main.js`, `components/`, `style.css`, `tokens.js`, `package.json`, `hyperframes.json`, `.gitignore`) into the project; `film.json`, `handoff.json`, `cues.js`, `anchors.txt`, `segments/`, `assets/`, `vendor/`, `renders/` stay. Components a director added stay and are listed. `--check` only lists differences.
- `npm run web-init -- <unit id> <seconds> [hand marks] [fonts dir]`: a silent loop unit for an article instead of a film (CARD.md, last section); the fonts dir is any folder `voice.py fonts --dir` filled.

Every command assembles first and stops with the command to run when the fonts are missing from the shared assets.

`film.json` `skill` tells the build where the skill's scripts are; when the skill moves, edit it or set `TEACH_VIDEO_ROOT`.

## Handoff contract

`handoff.json` `segments[]`: `id`, `start`, `end`, `lines` (narration line ids), `goal`, `hands`, `first`, `last`. In `first` / `last`, `state` is one sentence for people, `chapter` and `counter` (`{ value, unit, approx }` or `null`) are the chapter label and the counter at that moment, `items` are the objects that stay on screen and pass on (`kind` picks the stand-in, `box` is the outer box in screen px). Optional `seams[]` (`from`, `to`, `at`, `objects`); without it, seams follow from neighbouring segments. Optional `persist` (`{ "<id>": { kind, …stand-in fields, layer, from, to } }`): small objects that stay across segments and that no segment animates, such as one 示意 note for the whole film; `main.js` builds each from its stand-in on a layer above every segment and shows it from `from` to `to` (seconds, an anchor name or `"end"`).

- `ctx.take(id)` returns the object the previous segment gave, or a stand-in built from the description when that segment is not built or failed, so every segment can be written and checked alone. `ctx.give(id, obj)` hands over an object of `last.items`.
- `npm run check` verifies: neighbouring `last` and `first` are identical; at each segment's last frame every `last.items` entry was given, sits within 6 px of its `box`, is visible and is not covered by an opaque element created after it (hit-tested over its box); chapter label and counter match `last` and the camera is home; nothing visible is left in the segment's layers that was not handed over (not checked for the last segment).
- Stacking follows creation order within a layer: `F.shell` creates stand-ins in the order of `last.items`, and a receiving segment in the order it calls `ctx.take`. List and take a container (a window) before what sits inside it.
- Each segment has its own camera layer (`#seg-<id>`) and screen layer (`#scr-<id>`); a segment that throws is recorded and the others still build.
- Stand-in kinds: `term`, `ledger`, `labels`, `stamp`, `card`, `board`, `quote`, `sessions`, `grid`. To hand over anything else, add `F.standIn.<kind>` to a component first.
- `assemble` adds one empty marker per segment and seam (`#mk-<segment>`, `data-beat`), so the engine's `snapshot --review` sees segment boundaries and seams; the review packet relies on it.

## Engine version

HyperFrames is pinned in `starter/build/hf.cjs` (now 0.8.214); check, shots, render, `npm run dev` / `hf`, the browser the checks use, `scripts/voice/voice.py` transcription and the review packet all go through it. Projects already copied keep their own `hf.cjs` until `kit-sync`.

To upgrade, change the version and check a finished film made with the kit, in a copy:

1. `npm run check` on the whole film; for each newly reported issue, run the old version's `check --at` at the same moment to tell a new rule from different sampling.
2. `npm run hf -- snapshot --against <its renders/film.mp4> --at <≥ 12 moments covering every segment and seam> --no-end`, compare each pair (SSIM / PSNR), and compare old against new engine snapshots at the same moments.
3. `npm run render && KEEP_RAW=1 npm run finish` on the whole film and compare with the old film: frame count, length, per-frame PSNR, loudness, and subtract the audio tracks.
4. Do the same for one web loop unit.

The move to 0.8.214 (2026-10-29) passed this way on an approved three-minute film: 18 moments pixel-identical between engines, a full re-render within the old engine's own render-to-render variation (lowest frame 52.7 dB, both ways), audio identical after subtraction, −14.3 LUFS and −1.7 dBTP.

## Measured

- The demo (2 segments, 24.2 s): `npm run check` passes with geo 0, page 0 and engine check 0 errors in about 11 s; the selftest runs geo-check and the page-check cases on it.
- A 3:18 film with three segments: `npm run check -- --no-hf` on the stand-in skeleton takes about 3 s; the full `npm run check` on the finished film about 40 s (page checks about 3 s, the engine's check seven 30 s jobs, three at a time).
- On the source film, from copying the starter to an example segment passing check took 74 s and two rounds for the agent that had just extracted the components; an agent new to them reads this card and the component headers first (estimated 5–10 minutes, not yet measured).
- `npm run init` on a 3-minute narration with three segments produced the same scene-change boundary a director had written by hand; 122 of 136 hand-placed anchors were reproduced within one frame by words alone, the other 14 needed a written shift (deliberate leads or lags, rounding).

## Known limits

- Hand marks are counted per checked range; the film-wide cap of 4 needs one full-film `npm run check` by the director, who assigns `hands` per segment.
- The presenter reserve is checked on the page every 1/15 s, not on the rendered film; only frames where a painted element's box comes within 40 px of it are compared pixel by pixel; `finish` checks only the caption zone in the film.
- Font subsetting runs fonttools through `uvx` (downloaded the first time); a new character in any segment triggers a re-subset on the next command.
- `index.html` is regenerated by every command (identical content is not rewritten); while several segments are checked at once, a segment file with a syntax error only drops that segment.
- The empty-frame thresholds in geo-check were calibrated on this kit's light paper; a dark kit needs new thresholds.
